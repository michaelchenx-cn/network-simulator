## 课时 1 · 连入网络：IP 地址与通信路径

对应课本：第 6 课《数字身份辨设备》、第 8 课《路由路径靠算法》（融入第 4 课"存储转发"思想观察）

### 实验一　查看与配置 IP 地址（15 分钟）

**实验目的**　知道 IP 地址的作用与点分十进制表示；体会"同一网络中 IP 不可重复、地址必须合法"。

**实验步骤**

1. 新建拓扑：工具栏依次点击 **PC → 交换机 → PC**，在画布上各单击一次放置两台 PC 和一台交换机（PC1、PC2、Switch1）；再点击 **⇌ 连线** 按钮，依次点击 PC1→Switch1、PC2→Switch1 完成连线。
2. **双击 PC1** 打开终端，输入 `ipconfig` 回车，观察显示结果并记录。
3. 单击选中 PC1，在右侧属性面板的 **IP 地址**栏填入 `192.168.1.10`，子网掩码选 `255.255.255.0`（填写后点击画布空白处使其生效）。
4. 再在终端执行 `ipconfig`，与第 2 步对比。
5. 同样为 PC2 配置 `192.168.1.20 / 255.255.255.0`。
6. **合法性测试**：把 PC1 的 IP 改成 `192.168.1.260`，观察系统的反应；再改回 `192.168.1.10`。
7. 在 PC1 终端执行 `ipconfig /all`，找到本机网卡的**物理地址（MAC）**并记录——这是设备在局域网中的"另一个身份"。

**实验记录**

| 观察项 | 记录 |
|---|---|
| 未配置 IP 时，`ipconfig` 显示的 IPv4 地址是 | ______________________ |
| 配置后 PC1 的 IPv4 地址 / 子网掩码是 | _________ / _________ |
| 该地址属于（课本 6.1）：□ 公用地址　□ 私有地址 | |
| 把末位改成 260 后系统的提示是 | □ 地址不合法　□ 地址冲突 |
| PC1 网卡的物理地址（MAC）是 | ______________________ |

**思考**：课本第 6 课实验中"把本机 IP 改成教师用机的 IP"一步，在真实计算机上会提示什么？为什么模拟器中两台设备配相同 IP 不会报错？（提示：模拟器未模拟"地址冲突检测"，这一观察点需在真实计算机上完成）

### 实验二　ping 连通测试与"看不到的准备工作"（10 分钟）

**实验目的**　会用 `ping` 检测设备是否接入网络；知道 ping 之前系统先要完成 **ARP 地址解析**（对应课本 6.1"IP 地址与 MAC 地址两级标识"的思想）。

**实验步骤**

1. 点击底部 **【抓包】** 标签，确认"捕获点"为**所有链路**。
2. 在 PC1 终端执行：`ping 192.168.1.20`
3. 观察：① 终端里的回复信息（字节 / 时间 / TTL）；② 画布上先后**飞过的小方块**（第一个是黄色的 ARP 广播，之后才是青色的 ICMP）。
4. 在抓包列表中点击**第一条 ARP 报文**，右侧会展开"逐层解码"，找到"目标 MAC: FF:FF:FF:FF:FF:FF（广播）"字样。
5. 在 PC1 终端执行 `arp -a`，记录缓存内容。
6. 在 PC2 终端执行 `ping 192.168.1.10`（反向测试）。

**实验记录**

1. ping 通时每条回复显示：字节 = ____、时间 = ____ms、TTL = ____。
2. 抓包列表中，排在 ICMP 之前的报文协议是 ________，它的目标是 ________（单播 / 广播）。
3. `arp -a` 查到 192.168.1.20 对应的物理地址是 ______________________，与实验一记录的 PC2 MAC 是否一致？□ 一致　□ 不一致

### 实验三　默认网关与 tracert 路径追踪（15 分钟）

**实验目的**　会用 `tracert` 追踪通信路径并数出经过的路由器；理解"默认网关 = 通信的第一个路由器"（课本 8.1、8.2）。

**实验步骤**

1. 点击工具栏 **【实验】**，加载 **实验 2 · 跨网段通信与静态路由**（拓扑：PC1—R1—R2—PC2，若面板提示验证未完成可忽略）。
2. 双击 PC1，执行 `ipconfig`，找到**默认网关**一行——它就是通信要经过的第一个路由器。
3. 执行 `tracert 192.168.2.10`，观察逐行输出（模拟器中报文每经过一台路由器被称为一跳）。
4. 数一数：到达目的地共经过 ______ 个路由器（不含本机和目标）。
5. 单击画布上的 Router1，在右侧查看它的**静态路由**表；有条件的同学可在 Router1 终端执行 `show ip route` 对照。
6. **故障体验**：选中 **Router1—Router2 之间的链路**（中间那条），在属性面板点击 **断开**；再次 `tracert 192.168.2.10`，观察哪一跳开始出现"请求超时"（提示：第 1 跳 Router1 仍能正常应答）；观察完成后把链路恢复（连通）。

**实验记录**

1. PC1 的默认网关是 ____________，对应拓扑中的 ________（设备名）。
2. tracert 输出共 ____ 跳，每一行显示 ____ 个时间值。
3. 断开中间链路后， tracert 第 1 跳 ________（正常应答 / 超时），从第 ____ 跳开始显示"请求超时"。
4. 依据课本 8.2：路由器转发依据的是 ________ 表，表中主要记录的是"下一站"而不是最终目的地。

## 课时 2 · 看见协议：连接、握手与组网

对应课本：第 5 课《网络协议分层设》（netstat）、第 9 课《数据传输有新意》（三次握手）、第 10 课《综合所学建网络》（组网实践）

### 实验四　netstat 与 TCP"三次握手"（20 分钟）

**实验目的**　通过 `netstat` 观察 TCP 连接状态；借助抓包工具分析出"三次握手"SYN → SYN·ACK → ACK 的过程（课本 9.2 学习活动 3）。

**实验步骤**

1. 点击工具栏 **【实验】**，加载 **实验 4 · TCP 三次握手与四次挥手**（PC1 + Server1）。
2. **先看"无连接"状态**：PC1 终端执行 `netstat -an`，此时连接表中没有任何 PC1 的连接。
3. **发起连接**：执行 `telnet 192.168.1.20`。连接后随意输入一行文字回车（会收到服务器回显），**不要退出**。
   > 注意：telnet 会话期间，PC1 终端里输入的内容都会作为消息发给服务器，**不能再执行命令**——真实的 telnet 也是这样。
4. **再看"已连接"状态**：**双击画布上的 Server1**，在**服务器**的终端执行 `netstat -an`，可以看到一条状态为 **ESTABLISHED** 的连接（服务器视角：本地地址是服务器，外部地址是 PC1）。把两边的地址和端口记下来。
5. **观察握手报文**：打开底部【抓包】面板，找到三条开头的 TCP 报文（SYN → SYN·ACK → ACK）。依次点击，在右侧"逐层解码"中展开 **Ethernet II → Internet Protocol → TCP** 三层，记录每条的源/目的 IP 和端口、标识（Flags）。
6. **慢放重演**（教师演示或两人一组）：点击 **⏸ 暂停** 仿真，在 PC1 重新执行 `telnet 192.168.1.20`，然后连按 **⏭ 单步** 按钮，逐帧观看 SYN 飞出 → SYN·ACK 飞回 → ACK 飞出的完整握手。
7. **挂断观察**：输入 `quit` 退出会话，立即再执行 `netstat -an`，可以看到状态 **TIME_WAIT**（等待 2MSL 后彻底关闭）——这一步观察的是"四次挥手"之后的收尾状态。

**实验记录**

1. 服务器终端 `netstat -an` 中 ESTABLISHED 行：本地地址（服务器侧）____________，外部地址（PC1 侧）____________，状态 ________。
2. 三次握手报文（按顺序）：

| 次序 | 源 IP:端口 | 目标 IP:端口 | 标识（Flags） |
|---|---|---|---|
| 1 | | | |
| 2 | | | |
| 3 | | | |

3. 一次 TCP 连接由 ____ 次报文交互建立；对照课本图 9.5，第 1 步发起方发送的标识是 ________。
4. quit 之后 netstat 显示的状态是 ________，说明连接 ________（立即 / 延时一段时间）彻底释放。
5. 抓包中每条报文从外到内分为 ____ 层，分别是 ________ → ________ → ________，这体现了课本第 5 课讲的 ________ 思想。

### 实验五　综合组网：搭建校园直播网络（20 分钟）

**实验目的**　综合运用硬件选择、连接方式与网络参数设置知识，搭建具有"直播"功能的小型网络并用 ping 验收（课本第 10 课）。

**任务需求**（对应课本 10.1~10.3）

校园读书节要在**两个房间**同时直播：A 房间有主播用的 PC0（推流机）和直播服务器；B 房间有两台观看用的 PC。两个房间各自是独立网段，通过一台路由器互联。

**实验步骤**

1. **清空画布**（工具栏【清空】），按需求放置设备并连线，参考拓扑：

   ```
   PC0 ── Switch1 ── Router1 ── Switch2 ── PC2
                       │
   Server1 ────────────┘（直播服务器）
   PC1 ──（同 Switch1）
   ```

2. **规划地址**（自拟并填入记录单）：A 网段使用 `192.168.10.0/24`，B 网段使用 `192.168.20.0/24`。
3. **配置参数**：给每台设备配置 IP / 子网掩码；给 Router1 的两个接口分别配置两个网段的网关地址；给两边的 PC 配置**默认网关**。
   - 提示：直播服务器应使用 **静态** 地址——本模拟器中所有地址均为手工配置，正好对应课本"服务器用静态 IP"的要求。
4. **验收测试**：
   - PC2 `ping` 服务器地址 → 应通；
   - PC2 `tracert` 服务器地址 → 记录经过的跳数；
   - Server1 终端执行 `netstat -an`，确认 80 端口处于 **LISTENING**（直播服务待命）。
   - PC0 执行 `http <服务器IP>`，模拟"访问直播页面"，观察是否出现 `HTTP/1.1 200 OK`。
5. **故障排查演练**（对应课本 10.3 第 4 点）：教师或同组同学暗中制造一处故障（断开某链路 / 改错某台设备的掩码或网关），由你用 `ping`、`ipconfig`、`tracert` 定位并修复。

| Server1（直播服务器） | | | | |
| PC1、PC2（观看机） | | | | |
| Router1 接口 A / B | ______ / ______ | | — | |

## 附录 B · 教师提示

1. **课前 5 分钟**：演示"双击设备开终端"，这是学生最常卡住的操作（单击=选中，双击=开终端）。
2. 报文配色速记（可板书）：**黄=ARP　青=ICMP　绿=SYN　蓝=数据　橙=FIN　红=错误/RST**。
3. 实验四的单步演示建议全班同步：教师操作 ⏸ → telnet → 连按 ⏭，每帧提问"这是什么报文、从哪到哪"。
4. 实验五的"故障排查演练"可两人一组互相设障，对应模拟器内置【实验 5】的进阶玩法。
5. 学有余力：让学生给 Router1 删除静态路由再恢复，观察"单边路由"导致的超时现象（对应课本 8.3 安全话题的引申）。
